# Rubric: is this reproduction package ready to post?

Every check reads the package against the issue it belongs to. Locations
in the Evidence column ("the environment record", "the artifacts", "the
claim comment", "the repo-facts block") are defined in
`references/evidence-guide.md`. Grade the proof, not the polish: a terse
report can pass every check, and a long, confident, well-formatted one
can fail them.

## Checks

| Check                        | Evidence                                                                                                                                                                                                                                                  | Pass condition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Weight    |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| env-recorded                 | The repro report's environment record (evidence guide: Environment), read against the environment factors the issue body and thread say matter (driver, build profile, shell, browser language, dependency version, etc.)                                  | The report states (a) the version of the software under test and (b) the platform it ran on (OS, or the hosted playground / browser when the repro runs there), AND every environment factor the issue or thread names as deciding the behavior is recorded. Fails if the report has no environment record at all, even when the steps and output look right.                                                                                                                                              | required  |
| env-matches-target           | The versions and build named in the environment record, read against the version / branch / build the issue says is affected (issue body, template checkboxes, maintainer comments in the thread highlights)                                                | The tested version and build are the one the issue targets or newer, OR the report explicitly names the difference and treats it as a limitation. Fails when the report tests an older version, or a different build or channel than the one the issue or maintainers say is affected, without saying so; also fails when it names the difference but presents it as extra confirmation (e.g. "this shows the bug is not limited to X") without evidence of the issue's behavior on that build.            | required  |
| steps-followable             | The repro report's steps and every input they use (files, configs, layouts, scripts), inline or linked (evidence guide: Steps)                                                                                                                            | A stranger with only the posted comment could re-run the steps from a named starting state to the trigger: every command is given, and every input the steps depend on is shown inline, publicly linked, or is the issue's own published reproduction. Fails if any step depends on something private or unshared (a private repo, an internal config, "our pre-commit hook"), or if the report has no steps at all.                                                                                       | required  |
| steps-hit-trigger            | The commands and inputs in the steps, read side by side against the issue's reproduction or stated trigger condition (evidence guide: Steps, "trigger fidelity")                                                                                          | The steps exercise the trigger the issue describes: same command shape, same syntax, same input features the issue or thread says are required. Differences are acceptable only if the report names them and they do not remove the trigger. Fails if the input or command was changed in a way that removes or replaces the trigger (a different operator or separator, a different range syntax, a variable left unbound, a required flag or driver omitted), whether or not the report notices.       | required  |
| behavior-shown               | The artifacts in the repro report (output excerpts, logs, tracebacks, exit codes, rendered output) read against the specific behavior the issue describes (evidence guide: Behavior shown)                                                                | EITHER the artifact itself displays the issue's specific behavior (same failure kind: crash vs graceful error, same error message class or exit code, same wrong output, same missing element), OR the report is an explicit cannot-reproduce and the artifact shows the outcome of running the issue's trigger. Fails if there is no artifact, if the artifact shows only setup or that the program runs, or if it shows an adjacent behavior (a different error, a graceful error where the issue reports a panic, garbled output where the issue reports a crash). | required  |
| claims-backed                | Every sentence in the claim comment and repro report that asserts reproduction, certainty, or a cause, read against what the artifacts actually show (evidence guide: Honesty)                                                                            | Each claim of "reproduced", "confirmed", "verified", or a root cause is supported by an artifact in the package, and the stated expected / actual match what the artifact shows. An honest cannot-reproduce passes when it says so plainly, shows the attempt, and names what differed from the report. Fails on a diagnosis or certainty with no shown evidence ("I verified the race", "guaranteed reproducible"), or when the narration describes the artifact as something it is not.                   | required  |
| claim-specific-and-honest    | The candidate claim comment, read against the issue title and body (evidence guide: Comms)                                                                                                                                                                | The claim comment refers to this issue's specific behavior and states a concrete, modest next step. Stating an intended next step or "I'll report back" is fine. Fails if the comment could be pasted onto any issue unchanged (praise plus "please assign me"), is a bare +1 / me-too with no intent, asks for the issue to be reserved, or promises a deadline or a guaranteed outcome ("fixed in 2 days guaranteed").                                                                                     | required  |
| ai-policy-respected          | The contribution-policy line in the repo-facts block, read against the claim comment and repro report. Course packages are AI-assisted work (evidence guide: Comms, "AI policy")                                                                          | If the policy requires disclosing AI use in issues or comments, the comments contain a disclosure. If the policy requires comments in the contributor's own words, the comments read as first-person and specific to this issue, not boilerplate. If the policy bans AI-assisted contributions of this kind outright, fail. If the policy is silent, or its disclosure requirement applies only to pull requests, pass.                                                                                      | required  |
| control-run                  | The repro report's artifacts                                                                                                                                                                                                                             | The report shows a control run (the same steps with the trigger removed or changed) whose output differs in the way the issue predicts.                                                                                                                                                                                                                                                                                                                                                                  | preferred |
| template-asks-covered        | The bug-report template line in the repo-facts block, read against the repro report                                                                                                                                                                      | Each item the repo's bug-report template asks for (version, OS, install method, logs, etc.) is present in the report or its absence is explained.                                                                                                                                                                                                                                                                                                                                                         | preferred |

## Verdict rule

Accept if and only if every `required` check passes. Any `required` check
graded `fail` or `unclear` makes the verdict reject: proof that cannot be
verified from the package is not ready to post.

`preferred` checks are graded and reported but never change the verdict.

A check whose condition does not apply to the package (for example,
`ai-policy-respected` on a repo with no stated AI policy, or an issue
that names no deciding environment factor beyond version and OS) is
graded `pass`, not `unclear`.
